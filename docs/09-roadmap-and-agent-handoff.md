# 09 · 交付路线与 agent 协作

当前实现工作包：[WP-GAMEPLAY-REFOUNDATION-06](work-packages/WP-GAMEPLAY-REFOUNDATION-06.md)。当前设计入口为 01–12；旧 SHELL-05 只说明已有工程和历史证据，不再限制“不能改 Domain/Application/Save”。实现负责人可重构核心，但必须保留身份、确定性与旧档边界。

## 同一工作包的分阶段交付

| 阶段 | 交付物 | 退出条件 |
| --- | --- | --- |
| A · 核心可玩性 | 最新代码核验与过期合同治理；R1 从真实入口可玩；必要世界/语言/恢复基础 | 两种机制解法和可恢复失败确实成立，不能只做引擎或平行 Demo |
| B · 完整章节 | R2/R3、回访、工坊、词语册；有限词表/句型与教学支持 | 同一规则跨关复用，章节与各表面往返/恢复完整 |
| C · 体验与可靠性 | 因果动画、输入/布局/资源/音频、旧档迁移与必要回归 | 正常和异常 HTTP 路径验证，问题实际修复，证据绑定 SHA |
| D · 外部验收/发布 | 教研、素材/音频审核、真机、儿童观察、已授权托管验收 | 只按真实结果更新，缺条件保持 PENDING/BLOCKED |

A 的游戏性结构不成立时，先修改问题、工具和规则，不继续堆 B 的内容。A 工程达标即可继续 B/C；不以缺少实时 AI 凭据或外部审核为由停止所有开发。本包不是“先做 A 然后自动宣布完成”，也不是一次交付完整商业平台。

## 开工与文档治理

读取 README、STATUS、AGENTS/CLAUDE、01–05、07–12、当前工作包和真实代码；核对本地工作树、最新 origin/main、完整 SHA 和相关未合并改动。只核对本次影响范围，不再次输出整篇现状审计。

清理冲突旧设计、死链接、失效 Prompt/引用后再编码；保持同一权威文档，不增设平行蓝图。历史证据和必要 decoder/fixture 保留并标明历史，不删除它们来隐藏失败。内部里程碑变化写工作包和 STATUS，长期决定写 01/10。

## 协作与 Git

一个实现负责人完成一个包；第二个 agent 只能审查或承担明确不重叠工作，独立 worktree，不同时改共享 Domain/Content/Save/lockfile。共享协议由负责人协调。

本次实现用户明确授权独立分支、阶段提交、推送与 PR；未授权合并或部署。之前文档直接 main 的授权不扩张为本次自动合并。不强推、不覆盖无关修改。远端前进时重新读取与整合，不能把旧基线覆盖回 main。

允许自主调整类/文件名、布局和具体关卡细节，但不能减少 02/05/08 的验收语义。依赖变化必须有具体需求，实际安装并提交真实 lock；不假定新增引擎或状态库是工业级要求。

## 交付格式

报告 baseline/final full SHA、分支/PR、正式入口变化、实现与未实现、实际命令/退出码/环境、场景证据、发布限制。工程/视觉/真机/教研/趣味/发布分别标状态。运行未执行为 NOT_RUN，条件受限为 BLOCKED；不能沿用历史 PASS。

代码前最后核对文档，代码后只回写实际变化。提示词入口见 [Codex 执行提示词](prompts/codex-gameplay-refoundation-06.md)，细节在合同而非重复塞满 Prompt。
