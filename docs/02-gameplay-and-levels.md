# 02 · 玩法规则与章节设计

版本：Refoundation 06 / 目标设计，尚未实现或教研通过。本文是玩法与验收语义的权威；实现合同见 [05](05-content-and-runtime-contracts.md)，技术落点见 [12](12-web-game-technical-design.md)。

## 核心循环与操作边界

观察问题 → 理解已提供的词义 → 自选对象/工具/次序 → 提交行动 → 看见后果 → 调整或前进。游戏给目标，不提前给完整解法。目标以世界状态判定，不以某条参考操作序列判定。

场景操作统一为选择、移动/使用、有限造物、属性改变、开/关、放入/放上、取出、观察与撤销。点击选择后点目标，与拖放执行同一命令。拖动是提出搬运意图，不是越过围栏或把封闭容器里的东西瞬移出来。合法落点不得泄露唯一解法：显示物理可交互范围，不直接高亮正确英语答案。

WordSpell 造物先展示意义，采用内容声明的配额与稳定实例；不要求每次使用已学工具都重复拼写。small/big 印块是词义工具，不伪装成完整句法测评。句子工具用于明确的语言任务和角色指令；描述句只核对眼前状态。

## 可组合规则

| 规则 | 对玩法的实际影响 | 边界 |
| --- | --- | --- |
| 大小 | 影响通道净空、容器容纳、支撑高度和能否搬运 | 不是只缩放贴图；有限离散等级，由内容配置 |
| 空间/路线 | 对象、角色和目标之间须存在允许的交互或搬运路线 | 不强制自由摇杆移动；点击可规划受控路径 |
| 开合 | 决定门的通行和容器内容物可接触性 | Open 必须有合法操作者和可达把手，不能远程穿墙开门 |
| 支撑/容纳 | on 提供明确支撑，in 受开口与容量约束 | 含人/物的支撑不能缩小使其消失，非法变更拒绝并说明 |
| 身份 | 物品变化仍是原实例；造物是新实例 | 不复制主角/关键物，不用换图制造两个重叠实例 |
| 观察 | 读取实际可见对象、属性和关系 | 不搬物、不透露封闭容器里尚不可见的答案 |

为解谜提供“魔法作用范围”与“角色行动范围”两类一致规则：已学印块可以作用于当前可见且内容允许的对象；角色移动、搬运、开门必须遵守可达性。不可为某条预定解法临时例外。不可见、被遮挡或当前不允许的对象提供中性原因，不误报语言错误。

## 新章节建议：把野餐篮带回来

以下空间为制作合同草案，不是已经求解验证的关卡。实现者可以调整布局、美术和命名，但必须保留教学目的、真实规则差异和对应验收。每关声明初始状态、目标谓词、语言目标、可用操作、示范、帮助、可解路径和资源。

### R1 · 围栏那边的篮子（首个纵向切片）

目标：篮子和小猫到达围栏外指定区域。初态：门关闭，外侧把手较高，内侧把手可低位操作；围栏下有仅 small 角色可通过的洞；外侧有可搬运的箱子或一次 box 制作机会。先用非答案式演示介绍大小与点击/拖动，不给出路线。

至少支持两种机制不同的方案：A，把箱子移到门边再变大作为台阶，角色够到外侧把手并开门；B，让同一主角变 small，穿洞到内侧，操作低位把手开门，再取回篮子。尺寸改变不改变主角词形或实例 ID。路线、把手高度和箱子承载均由规则计算，不能用“做过 big”“看过缩小动画”代替。

内容必须明确取篮子和返程的可达条件。若其他合法组合能达到目标，应接受；不能为了凑两解而封禁第三种正确办法。两条脚本换序不是两种解法。受阻尝试至少覆盖错误对象变大、箱子太小不够高、直接拖篮子穿围栏；均可撤销或调整。

验收：从正常首页分别实际完成 A/B；两条轨迹的关键通行/支撑条件不同。刷新和 reduced-motion 不改变结果；无注入通关状态；目标完成不依赖特定学习日志顺序。

### R2 · 东西装不进去（复用属性与容纳）

目标：把指定物品装入合适容器并送到集合点。初态：存在开合状态明确的 bag/box、尺寸不匹配的物品和可见目标。先教 open/close、in 的意义；学习内容之外不额外堆语言难度。

主要决策来自“改变物品尺寸还是改变容器/选择另一容器”“先打开还是先取出调整”，不是找唯一按钮。至少一个搬运或入口条件阻止所有东西无限变大成为万能解；条件必须在画面中可理解。容器和内容物移动必须整体保持身份关系。合法替代路径按目标接受。

验收：同一容量/净空规则在另一对象上成立；已装入物品不会因缩容消失；关闭容器时不能直接取物；Open/Put 的正确句子遇世界阻挡时保留语言正确和草稿。

### R3 · 送到朋友需要的地方（组合应用与结局）

目标：理解一条短请求，把指定物品送到合适的支撑/容器位置，并让小猫能够抵达。复用 R1 的门/路径与 R2 的尺寸/容纳，不引入新的大型系统。可采用纸屋或高低台架布局，由实现者使位置关系直观。

至少有一个由英语请求决定的实际选择，如 in 与 on 对应不同放置关系；不能只凭固定槽位或颜色完成独立检查。指令执行后用描述回顾实际布置。描写正确但对象/关系不符合请求时，明确为“表达成立、任务未满足”。剧情结局读取真实交付物和选择，可继续观察或进入回访。

验收：不同合法准备顺序可完成；语言目标并非附加在解谜后的无关问答；两块 the 独立；当前世界不能被描述句修改；正常与辅助路径分别记录。

### R1-R · 条件改变的回访

返回熟悉场景，但更换一个对解法有影响的约束，例如洞口关闭、支撑落点变化或容器净空变化。必须重新验证可解，不使用任意随机布局。不是把道具换色，也不是原关同路径再来一次。

允许重听、提示、退出；回访开始新的评估实例但保留历史帮助。没有足够延迟或独立证据，不能宣称长期记忆。首版采用手工变体和固定 variant/seed；刷新恢复同一变体，明确重玩才变更。

## 学习与开放探索分离

教学任务可有明确目标；开放谜题不能把所有非指定动作都判错。ExerciseSpec 声明本题语言目标与接受表达；PuzzleSpec 声明世界目标与可用规则。成功解谜不自动证明每个词都学会，也不要求先填写完课程清单才允许合法解法生效。

新知识采用看图/动作/听音 → 辅助试用 → 独立应用 → 不同条件回访。语言负荷按内容审核控制，不将约三关的章节装入完整英语课程。

## 反馈、恢复与趣味

反馈先展示因果，再用一句可操作提示；重复受阻反应缩短，不长时间锁住输入。角色幽默表达发现、尝试和小困惑，不羞辱玩家。无生命、强制倒计时、惩罚性扣分或连续签到。

撤销回退完整一次世界行动，保留历史语言尝试与已经提供的帮助；再做不会刷新资源配额或伪造首次独立成功。重开、回访、工坊与主章节各自保存会话边界，离开工坊不能把道具带入关卡绕过配额。

## 旧故事兼容不变量

route-sheet 的 map/mat 始终为同一实例，旧主线必须铺路并过墨才可恢复 map；cat-companion 与 cat-card 分离；picnic-mat 独立；旧 craft-mat/craft-hat 配额保留。新属性操作不能被解释为解除旧故事的物种变形保护。旧三幕、六词、十二挑战和十三步骤均不是新章节的全局限制。
